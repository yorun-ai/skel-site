# 项目目录

## 单文件模式

做实验或者写个小契约的时候，直接传一个 `.skel` 文件就行：

```bash
skelc check --skel-in ./user.skel
```

## 目录模式

正式 domain 推荐用目录来组织：

```text
user/
├── skel/
│   ├── domain.skel
│   ├── model.skel
│   └── service.skel
├── skeled/
└── pub/
```

`domain.skel` 只负责 domain 声明和可选的说明文字；其他文件声明同一个 domain，按职责拆开。skelc 按文件名字典序加载，隐藏文件、子目录和非 `.skel` 文件会自动忽略。

## 外部 domain

先在 Skel 里声明逻辑依赖：

```skel
import demo.user as user
```

生成时再给物理映射：

```bash
--skel-import demo.user=../user/pub/skel
```

逻辑 domain 名保持不变，路径和语言包名交给构建环境去映射。Go 和 TypeScript 生成分别用 `--go-import`、`--ts-import`。

## 输出所有权

生成器会在每个输出顶部附近写入 `Code generated by skelc. DO NOT EDIT.`
标记，因此不需要额外的 manifest，也能让生成文件和手写文件共享目录。不带标记的
文件不会被删除。重新生成时，会删除带有生成标记、但已不再需要的文件；不过手写文件
一定不要与本次生成文件使用同一路径，否则下一次生成会直接覆盖它。
